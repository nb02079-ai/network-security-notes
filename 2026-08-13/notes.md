## 1. 서브네팅(Subnetting)
같은 네트워크에 속한 주소를 **논리적으로 여러 네트워크로 나누는 과정**.

| IP | 마스크 | 네트워크 주소 |
|---|---|---|
| 192.168.16.100 | 255.255.255.128 (/25) | 192.168.16.0 |
| 192.168.16.200 | 255.255.255.128 (/25) | 192.168.16.128 |

→ 두 호스트는 서로 다른 네트워크로 취급되어 라우터를 거쳐야 통신한다.

```
서브넷 마스크 11111111.11111111.11111111.00000000
              └──────── Network ID ────────┘└ Host ID ┘
```

### 핵심 규칙
- 각 서브넷의 **첫 주소 = 네트워크 주소, 마지막 주소 = 브로드캐스트** → 호스트에 할당 불가
- 많이 나눌수록 할당 불가 주소가 늘어나 **쓸 수 있는 호스트 수는 줄어든다**
- 원래 쓸 수 있던 주소(.128 등)도 서브네팅 후엔 네트워크 주소가 되어 못 쓸 수 있다

### 계산 표
| 프리픽스 | 마스크 | 블록 크기 | 서브넷 수(/24 기준) | 호스트 수 |
|---|---|---|---|---|
| /25 | .128 | 128 | 2 | 126 |
| /26 | .192 | 64 | 4 | 62 |
| /27 | .224 | 32 | 8 | 30 |
| /28 | .240 | 16 | 16 | 14 |

- /26 → 0~63, 64~127, 128~191, 192~255 (사용 가능: 1~62, 65~126, 129~190, 193~254)
- /27 → 0~31, 32~63, … , 224~255 (사용 가능: 1~30, 33~62, 65~94, 97~126 …)
- 나눈 네트워크를 다시 나눌 수 있다 (예: 192.168.16.0/25 → /27 네 개) → **VLSM**

### 실습: 192.168.100.0/24를 8개로 나누기 (/27)
| 대역 | 용도(필기 예시) |
|---|---|
| .1 ~ .30 | PC 12대 |
| .33 ~ .62 | PC 34대 → **30대 초과라 /27로는 부족**, /26 필요 |
| .65 ~ .94 | PC 56대 → 마찬가지로 /26 필요 |
| .97 ~ .126 | 라우터 간 링크 |
| .129 ~ .158 | 라우터 간 링크 |

> 실무 팁: 호스트가 많은 대역부터 큰 블록을 배정하는 것이 VLSM의 기본 순서.

## 2. WAN 직렬 연결
- **DTE**(Data Terminal Equipment): 데이터 단말 장비
- **DCE**(Data Circuit-terminating Equipment): 데이터 회선 종단 장비 — 클럭 제공 (`clock rate` 설정은 DCE 쪽)
- 라우터 Serial 인터페이스에 주소를 설정해야 라우터끼리 통신 가능
- 라우터끼리 **경로(라우팅)** 를 설정해야 서로 다른 네트워크의 PC가 통신 가능

## 3. 라우팅 종류
| 구분 | 설명 |
|---|---|
| Static | 관리자가 직접 경로 설정 — 경로가 단순할 때 |
| Dynamic | 라우팅 프로토콜 알고리즘이 자동 설정 — 장비가 많거나 다중 경로일 때 |

- Dynamic 종류: RIP, EIGRP, OSPF (내부), **BGP** (AS 간·ISP 간 라우팅)
- 정적 라우팅은 라우터가 늘수록 **모든 라우터에 경로를 각각 등록**해야 한다

### 정적 라우팅 설정
```
Router# show ip route                       ! 라우팅 테이블 확인
Router(config)# ip route 192.168.20.0 255.255.255.0 192.168.24.200
                         └ 목적지 네트워크 ─┘ └ 마스크 ┘ └ 다음 홉(next-hop) ┘
```
- 다음 홉 = 목적지 방향에 있는 **이웃 장비의 IP**
- 라우팅 테이블 읽기: `S 192.168.20.0/24 [1/0] via 192.168.24.200`
  - `[1/0]` = [AD(관리 거리, 경로 신뢰도) / Metric]

## 4. RIP (Routing Information Protocol)
```
Router(config)# router rip
Router(config-router)# version 2
Router(config-router)# network 192.168.10.0     ! 직접 연결된 네트워크 광고 (마스크 X)
Router(config-router)# no auto-summary
Router# show ip protocols
```
- 거리 벡터 방식, Metric = **홉 수** (회선 속도 무시) → **최대 15홉**, 16은 도달 불가
- AD 값 120 (관리자가 변경 가능)
- 타이머: Update 30초 / Invalid 180초 / Flush 240초 (180초 후 60초 더 지나면 삭제)
- `maximum-paths 4`: AD와 Metric이 같은 경로를 최대 4개까지 동시 사용(부하 분산)

### 버전 차이
| | RIPv1 | RIPv2 |
|---|---|---|
| 방식 | Classful (마스크 전달 X) | Classless (마스크 전달 O, VLSM 지원) |
| 전송 | 브로드캐스트 | 멀티캐스트 224.0.0.9 |
| 자동 축약 | 항상 | `no auto-summary`로 끌 수 있음 |

- 버전 미지정 기본: v1 송신, v1·v2 수신 / `version 2`: v2만 송수신
- 인터페이스별 조정: `ip rip receive version 1`
- 자동 축약 때문에 원치 않는 대역까지 묶여 통신이 꼬일 수 있다 → v2 + `no auto-summary`

## 5. 정정·보충
- 원본의 "Hello packet" → RIP는 Hello가 아니라 **라우팅 업데이트**를 주기적으로 보낸다. Hello는 EIGRP·OSPF 용어.
- DCE의 C는 Circuit-terminating.
- PC 34대·56대는 /27(30호스트)에 들어가지 않으므로 /26 이상으로 배정해야 한다.
